# Чек-лист безопасного запуска Helena Fit

Документ описывает, что нужно сделать на боевом сервере **до и во время** выката
ветки `prelaunch-hardening`. Пункты со знаком 🔴 — обязательны, без них запускать нельзя.

> Все правки в коде уже сделаны и протестированы локально. Этот чек-лист — про
> действия на сервере и настройки окружения, которые делаются руками.

---

## 1. 🔴 Ротация скомпрометированных секретов

Эти значения лежали в Git в открытом виде, считаем их утёкшими — **перевыпустить**:

- [ ] **Токен Telegram-бота** — `@BotFather` → `/revoke` → новый токен в `TELEGRAM_BOT_TOKEN`.
- [ ] **Ключи Payme** (test и prod) — в кабинете Payme перевыпустить, обновить `PAYME_TEST_KEY` / `PAYME_PROD_KEY`. (Это пароль вебхука — критично.)
- [ ] **SSH-пароль root** сервера — сменить (`passwd`), а лучше перейти на ключи и отключить парольный вход.
- [ ] **Пароль БД** (`DB_PASSWORD`) и **`JWT_SECRET`** — сгенерировать новые длинные случайные значения.

Сами доступы хранить вне репозитория — в `CREDENTIALS.local.md` (он в `.gitignore`).

> История Git всё ещё содержит старые значения. После ротации они безвредны, но при
> желании историю можно почистить (`git filter-repo`/BFG) — это отдельная операция.

---

## 2. 🔴 Переменные окружения на сервере (`.env`)

Бэкенд теперь **падает при старте**, если не заданы критичные переменные
(`backend/src/config/env.validation.ts`). Проверь, что в серверном `.env` есть:

| Переменная | Обязательность | Примечание |
|---|---|---|
| `JWT_SECRET` | 🔴 обязателен, ≥16 символов | иначе старт прерывается |
| `DB_PASSWORD` | 🔴 обязателен | дефолта `postgres123` больше нет |
| `DATABASE_URL` | 🔴 обязателен | формируется в compose из `DB_PASSWORD` |
| `TELEGRAM_BOT_TOKEN` | 🔴 обязателен в проде | нужен для проверки подписи |
| `TELEGRAM_APP_URL`, `ADMIN_PANEL_URL` | ⚠️ иначе CORS = localhost | боевые https-URL |
| `PAYME_PROD_KEY` | ⚠️ иначе вебхук Payme не авторизуется | |
| `DISABLE_TELEGRAM_SIGNATURE_CHECK` | по умолчанию `false` | см. п.3 |

---

## 3. 🔴 Поэтапное включение проверки подписи Telegram

Добавлена строгая проверка HMAC-подписи `initData`. Чтобы исключить риск «не пускает всех»,
выкатываем в два шага:

1. [ ] Первый деплой — с рубильником: `DISABLE_TELEGRAM_SIGNATURE_CHECK=true`.
2. [ ] Проверить, что реальные пользователи **входят** (открыть Mini App из Telegram, профиль грузится, доступы на месте).
3. [ ] Убедиться, что `TELEGRAM_BOT_TOKEN` — актуальный (тот же, под которым работает Mini App).
4. [ ] Снять рубильник: `DISABLE_TELEGRAM_SIGNATURE_CHECK=false` (или убрать переменную) и передеплоить.
5. [ ] Снова проверить вход. Если вход сломался — временно вернуть `true` и разобраться (чаще всего причина — неверный токен бота).

---

## 4. 🔴 HTTPS + домен (обязательно для Telegram Mini App)

Mini App **не работает по HTTP**. Нужен домен и TLS-сертификат.

- [ ] Направить домен (напр. `helena-fit.ru`) на IP сервера.
- [ ] Поставить Nginx + сертификат Let's Encrypt (`certbot --nginx -d helena-fit.ru`).
- [ ] Использовать конфиг из `nginx.conf.example` (в корне репозитория) как основу.
- [ ] В `@BotFather` указать Menu Button URL на `https://`-домен.
- [ ] Пересобрать фронты с правильным `VITE_API_URL` (см. п.6).

---

## 5. Схема БД: остаёмся на `db push`

`docker-compose` теперь выполняет `prisma db push --skip-generate` (вместо `migrate deploy`).

- Это **идемпотентно** и без `--accept-data-loss` **не удаляет данные** (при расхождении схемы просто упадёт с понятной ошибкой).
- Миграции в Git **намеренно не включены**: прод собран через `db push`, и переключение на `migrate deploy` потребовало бы baseline существующей БД (`prisma migrate resolve --applied ...`). Это отдельная задача на потом — для запуска не требуется.
- [ ] Volume `postgres_data` не пересоздавать без бэкапа (там вся база и розданные доступы).

---

## 6. Сборка фронтендов

- [ ] `telegram-app`: собрать с `VITE_API_URL=https://<домен>/api`.
- [ ] `admin-panel`: собрать с тем же `VITE_API_URL=https://<домен>/api` (раньше указывал на голый IP по HTTP — это вызывало бы Mixed Content).
- [ ] Залить `dist/` каждого на сервер, раздать Nginx (telegram-app на `/`, admin-panel на `/admin`).

---

## 7. Прочие обязательные действия

- [ ] 🔴 Сменить пароль администратора (был дефолтный `admin123`). На странице логина подсказка с паролем убрана.
- [ ] Порт Postgres теперь слушает только `127.0.0.1:5434` — снаружи недоступен (для админ-доступа использовать SSH-туннель).
- [ ] Прод теперь стартует в `NODE_ENV=production` (`start:prod`), dev-login заблокирован.

---

## 8. ⚠️ Сознательно отложено (принятый риск)

- **Payme «оплати 1 сум»**: сумма заказа всё ещё приходит с клиента (`createPaymentLink`),
  сервер её не пересчитывает. Технически можно оплатить меньше реальной цены.
  Фикс правит **только** `createPaymentLink` и **не затрагивает** вебхук, который проходил
  модерацию Payme, — его можно сделать отдельно и безопасно, когда будешь готов.
- **Чистка отладочных `console.log` в `payme/*`** — не делалась, чтобы не трогать Payme-модуль.
  Логи безвредны функционально, но содержат фрагмент заголовка авторизации — стоит убрать
  отдельным мелким изменением.

## Что уже сделано в коде (ветка `prelaunch-hardening`)

- Проверка подписи Telegram `initData` (+ анти-replay, рубильник) — с юнит-тестами.
- `AdminGuard` на `admin-workout-sections` и `analytics`.
- Закрыта утечка платного контента (видео-секции, полный рецепт без доступа).
- Секреты вычищены из доков; сборка чинит Prisma-клиент (`prebuild`).
- Production-режим в Docker, fail-fast по env, `fileFilter` на загрузку, закрыт порт БД,
  healthcheck + ротация логов.
- Устойчивость фронтов: ErrorBoundary, обработка сбоев, устойчивый опрос оплаты, корректная
  обработка сбоя логина.
- Защита от удаления сборника с выданными доступами.
- Восстановлены ESLint-конфиги во всех трёх проектах.
